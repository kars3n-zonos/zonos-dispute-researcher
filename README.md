# Zonos Dispute Researcher (Tools)

A Tampermonkey script for the Zonos broker portal (brokerage.dashboard.zonos.com). Since 7.80.0 it works inside the portal's own tools instead of a Tools panel of its own: **Research in Claude Code** (or **Open in claude.ai**) in the portal's Research tool, with Claude's answer written into the dispute's **Notes** by itself; a fuller **Classify** inside the portal's Classify; an **Entry Assistant** button in the top bar; Analytics; and the optional Portal+ work queue with search and bulk actions.

**No keys are built in.** Each person adds their own under Settings, and every part is optional. Changes to the portal's own pages are **off** until you turn them on.

## Install

1. Install [Tampermonkey](https://www.tampermonkey.net/) in Chrome.
2. Go to `chrome://extensions`, open Tampermonkey's **Details**, and turn on **Allow User Scripts**. On older Chrome versions, turn on **Developer mode** instead.
3. Open the install link and click **Install** (or **Update**, if you have the old Dispute Researcher):
   **https://gist.githubusercontent.com/kars3n-zonos/9dd13b6c4c3ea4d1d6a876d45002c0a3/raw/zonos-dispute-researcher.user.js**
   (A secret link: share it only with people who use Tools. This repo is private; the link keeps working for Tampermonkey.)
   (If you installed "Zonos Dispute Desk (Sheets)" from `zonos-dispute-desk-sheets.user.js`, keep it: since 7.17.0 it's the same script. Install only one of the two.)
4. When Tampermonkey asks to allow a connection, choose **Always allow domain**.
5. Open **Manage account** (your avatar at the bottom of the sidebar) > **Tools**. Under **Dispute Deck** > Back up or move your setup, paste the setup block from Karsen and press **Import**. It connects you to the team's Google Sheet.

Updates install automatically: Tampermonkey checks this repo about once a day. To update right away, use Tampermonkey's **Check for userscript updates**.

Cases are tracked in the team's **Google Sheet** (since 7.17.0): one row per case, a Google Doc per case, and Comments, Prompts and Research tabs.

For the maintainer:
- Edit only `zonos-dispute-researcher.user.js`. On every push to `main`, a GitHub Action runs `build-sheets.ps1`, commits `zonos-dispute-desk-sheets.user.js` (the same script under its own name and update address), and publishes both to the secret gist Tampermonkey installs and updates from (needs the `GIST_TOKEN` secret, a token with only the "gist" scope).
- Raise `@version` with every change pushed to `main`, or Tampermonkey won't install it.
- The sheet's web app is `OctoberDisputes.gs` (kept outside this repo, since it holds the sheet's secret). After changing it: Deploy > Manage deployments > edit > Version: New version > Deploy.

## Where it shows up (since 7.80.0)

The portal now has its own top bar with **Research**, **Classify** and **Quote** (Research only on duty disputes), and its own Research tool with shared **Notes**. The script fits into those instead of opening a panel of its own: the Tools button, the Tools panel (its Research, Doc, Classify, Quote and Settings tabs, and the ◀ ▶ order strip) and the keyboard shortcuts are gone.

- **Research** (the portal's tool, duty disputes): **Copy prompt** is replaced by **Research in Claude Code** when a cloud routine is set up for you, otherwise by **Open in claude.ai**. Either builds the script's own research prompt (below) from every disputed line, with the order's documents, plus the team's **Notes** so far. How it's going shows under the button.
- **Back to the research chat** (since 7.82.0): once a dispute has a research chat (its Claude Code session, or the claude.ai chat started for it), the button becomes **Open Claude Code session** (or **Open claude.ai chat**) and opens it in a new tab; **Research again** beside it starts a new one. The chat links come from the Google Sheet (the case's research requests and its row's AI chat link) and from this computer.
- **Earlier research in Notes** (since 7.82.0): every past Claude answer and research chat of a dispute goes in its Notes, in an **Earlier Claude research** section after the current answers: a **Chats and links** list (Claude Code sessions, claude.ai chats, the case doc and sheet row, Front and Slack), then each past answer, newest first, with its date. They come from the Google Sheet's Research tab, the shared answers server and what's saved on this computer. It runs **by itself**: once on each computer after updating (live mode only), in the background, one dispute at a time, in one portal tab at a time, going through every duty dispute in the portal (open, waiting and closed); a reload carries on where it stopped. Where someone already filled a dispute in, a computer only adds what it alone has, without asking the Google Sheet again. A dispute you open is filled in by itself too (once a day at most), and **Manage account > Tools > Earlier research into Notes > Fill in Notes** runs it now, two at a time, and can be stopped and run again. Notes are shared, so one run fills them in for everyone; a teammate's run adds what only their computer had. Each run only adds what's missing: nothing already in the Notes is changed, and an answer already shown (or the same answer from another source) isn't added twice.
- **Claude's answer goes in Notes** by itself: Claude Code's when its research finishes (checked every 15 seconds while the dispute is open, and when you come back to it), claude.ai's as soon as the chat answers. It's a section at the top of the Notes, **Claude Code research** (or **Claude Code patent check**, or **Claude research (claude.ai)**), formatted for the Notes editor: headings, lists, tables as lists, with a link to open its Claude Code session or claude.ai chat. The next answer of the same kind replaces its section; everything the team wrote stays as it is. It's saved through the portal's own notes API with the version it read, so it never overwrites a newer save, and it waits while someone is typing in the Notes on that page. The answer also still goes in the Google Sheet and the case doc.
- **Classify** (the portal's tool): the portal's form gives way to the script's Classify (below), filled in from the order.
- **Quote** is the portal's own.
- **Entry Assistant** (since 7.81.0 a tool like the others): a button in the top bar after Quote opens it in the portal's own tool card, in the same spot, with the same header (overlay toggle and close) and fade-in. It follows the portal's **Open tool** setting (Manage account > Tools): laid over the page, where Escape closes it, or beside the page, moving it over; its overlay toggle changes that setting for every tool. One tool at a time: opening it closes the portal's open tool, and opening one of those closes it; pressing its button again closes it. Its only difference is its width, 842 px, just wide enough for the HTS table's seven columns; on a screen too narrow to leave the page 480 px beside that, it lays over the page. Codes clicked on the page open in it too, when that's turned on.
- **Settings**: under **Manage account > Tools**, below the portal's own Tools settings, in a **Dispute Deck** section. **Analytics** opens from there, in the same tool card (and from Tampermonkey's menu, with Entry Assistant).
- **Research again:** if a case was already researched (by anyone; the Google Sheet's Research tab says), the research button asks before starting another session, and bulk runs skip it.

## What's in it

- **Research:** builds a research prompt written for the dispute or the order's problem class.
  - Dispute prompts for both claude.ai and Claude Code include the initial AI verdict, reasons and suggested fix behind the **Automated - denied / accepted** hover tags. These carry substantially more weight than most context, while Claude still completes normal research, verifies the reasoning and explains any disagreement (since 7.62.0).
  - claude.ai prompts (Open in claude.ai) tell Claude to use only .gov sites when it looks for proof or cites any government entity; research on the merchant and product is unrestricted. Claude Code prompts don't carry this rule (since 7.63.0).
  - **Case type and specialist checks** (since 7.75.0): each case is routed the same way the Claude Code worker routes it (one path, plus the specialist checks its goods and claims call for: Pharmaceuticals, Section 232 metals, Partner agencies, Classification, Origin and trade agreements, Valuation, Tariff programs, Questionnaire). claude.ai prompts open with a **Case type** line (e.g. "Duty dispute → Pharmaceuticals · Partner agencies · Tariff programs · Questionnaire") and carry a "Specialist checks for this case" section with only those checks. Claude Code gets the full playbooks from `dispute-desk-cloud` instead. Reply templates in both get the specialists' lines (**Pharma:** with the drug, FDA approval, U.S. patents and the 9903.04 heading; **Agencies:**; and **Section 232:** on queue orders). Each specialist's text is editable in the sheet's Prompts tab (group "Specialist checks"; **Set up Prompts** adds the rows). Keep the routing rules in step with `route()` in the cloud repo's `worker.py`.
  - **Open in claude.ai** fills a claude.ai chat with the prompt and attaches the order's documents and images. Nothing is sent until you press Enter.
  - **Claude's answer** goes in the dispute's Notes in the portal (since 7.80.0, see above), with its one plain sentence first ("**Final answer:** It is out of scope because …").
  - **The team's notes:** the prompt ends with the dispute's Notes as the team wrote them (without Claude's own sections), so Claude builds on what's already been checked.
- **Questionnaire disputes:** the prompt includes what each "Disputed program compliance_program_…" is (e.g. "USMCA certification of origin"), with the questionnaire's questions and the merchant's answers.
- **Classify**, inside the portal's Classify tool: the same request as the portal's own Classify, filled in from the order (a line picker when a dispute has several, with the merchant's description where they claim one), and it gives the code in large type with a confidence meter, where it sits in the HTS (chapter, heading, subheading, tariff line), the customs description, a level-by-level check of a code you enter (fits / partly / doesn't fit), and the alternates, each with Copy, Open or Compare in Entry Assistant. (The duty calculator that could replace Quote is gone since 7.80.0; the calculator still runs for the research prompts.)
- **Analytics** (Manage account > Tools > Dispute Deck > Analytics): from every work order's own history in the portal: who resolved (and submitted) the most, who claimed, released, marked waiting, escalated and added notes, and the typical time from claim to resolve, for today, 7, 30 or 90 days or 12 months, by class. Also who holds how many right now (overdue and waiting), unclaimed orders, how orders were resolved, and new orders by company. **Export** gives every event as a CSV.
- **Entry Assistant:** the Entry Assistant site's framed pages (`?frame=code`, or `?frame=compare` when a line has two codes, since 7.77.0), in the window the top bar's Entry Assistant button opens: one slim bar instead of the site's header and menus, laid out for the window's size, filled in with the code (or both codes) and the country of origin you clicked. With no code clicked, it opens on the order's first code (since 7.79.0), and off an order it starts from its search box. **Open in a new tab** gives the full site; sign-in doesn't carry into the frame, so its AI features live there.
  - **Loaded ahead** (since 7.79.0, on unless turned off under Manage account > Tools > Portal pages): when an order opens, the Entry Assistant pages its codes lead to load in the background, so clicking a code or opening Entry Assistant shows them at once instead of after about a second. That's up to 4 per order, most likely first: an HS code review's pair, what a click on each code on the page opens, then the order's other codes. They load once the codes have settled on the page, invisible but at the size they'll be shown at, so the HTS table opens scrolled to the code. Moving to the next order drops the last order's frames except the one showing; at most 6 are kept at once.
- **Queue views:** **Default Portal** (the portal's own queue, the default) and **Portal+**. Pick one under Manage account > Tools > Portal pages, or with the picker on Portal+. (The Advanced View was taken out in 7.58.0; anyone who had it now gets Portal+.)
- **Completed tab** (Portal+, since 7.69.0): every resolved and auto-resolved order, everyone's, the same as the portal's own Completed tab (a submitted duty dispute's order is auto-resolved). It loads when you open the tab, then at most every 5 minutes or with ↻; the portal's `?scope=completed` address opens it too.
- **Search** in Portal+ searches every work order, open, waiting and closed, whatever tab is open (closed ones load the first time you search), and takes a pasted list of tracking numbers. Filters you set still apply; the default "hide escalated" doesn't. Clear the search to see the tab again.
- **Status column** (Portal+): the status on its own line, with short flags under it: red **✕ Res. failed** (the dispute was submitted but the portal couldn't finish resolving it), orange **↑ Eng** / **↑ Broker** (escalated) and **✦** (you researched it). Compact rows show just the symbols; hover any flag for what it means.
- **Escalated orders** are hidden from the queue's tabs while **Hide escalated orders** is ticked under Manage account > Tools > Portal pages (on to start with); "N escalated hidden" above the list says so. A search always shows them.
- **Only resolution failed** (a checkbox above the list) shows just the disputes whose resolution failed; it works on its own, and says when some are hidden because they're escalated.
- **Portal+** (optional): the portal's own queue as you know it, without its limits: one list that loads as you scroll, sortable columns that stay in view, search on anything, one-click Claim, details at once, select and bulk actions, and your place kept when you come back from an order. The list fills the window in its own scroll box, so in a half-width window it scrolls sideways instead of cutting columns off (since 7.60.0). Also: one-click counts (overdue, due today, due in 7 days, waiting, escalated, new), grouping (customer, class, assignee, status or due), compact rows, and a ✦ beside the status of every order you started research on (Claude Code or claude.ai, kept 60 days; filled purple while Claude Code is still researching).
  - **Bulk actions:** Claim, Release, Wait, Resume, Escalate, Note, Assign and Resolve (with the access code; without it you can still select and copy refs, links or a CSV). Each shows what will happen, and in which mode (LIVE / TEST), before anything is sent.
  - **Claim & research** (bulk bar, with the access code): claims the selected orders nobody has and starts Claude Code research on each, in the same paced background run as Research all.
  - **Patent check** (bulk bar, with the access code, since 7.73.0): a quick Claude Code check of only whether the drug on each selected order is patented in the US (FDA Orange Book, Purple Book for biologics) and whether generics are approved. Nothing is claimed. Each goes in the sheet's Research tab as a "Patent check" request, its answer lands in the case doc and Answer cell, and it never counts as the case's research, so Research still runs on it later. The cloud worker's `CLAUDE.md` ("Quick patent checks") keeps these sessions to that one question.
  - **Submit** (bulk bar, duty disputes): reads each selected dispute and submits only those whose every claim, on every line, has a saved decision (the same as its own Submit button), claiming unclaimed ones first. Each is read back afterwards, and a results list shows what was submitted, what wasn't and the portal's reason. **Resolve** skips duty disputes.
  - **Decide by reason** (bulk bar, duty disputes): offers each reason the selected merchants gave; picking one takes only the disputes that give exactly that reason on every claim of every line, then has one decision per kind of claim (since 7.74.0): its type, and for a questionnaire the program it claims (e.g. "Questionnaire · USMCA certification of origin" and "Questionnaire · Additional Duties"), each Accept (as proposed), Deny or Leave undecided, with its own note or the general one. Then it can submit the ones left with nothing undecided.
  - **Re-send as filed** (bulk bar, Entry rejected): the page's Streams and Send as for every selected rejected entry.
- **Batch work** (behind an access code in the settings): claim every unclaimed order of one class, then decide identical orders together. Orders are only grouped within one company, and disputes only when every disputed line's HS code, description, origin, claims, merchant reasons and questionnaire answers match exactly. Denied-party reviews are grouped when the screening flagged the same party (the same name, address and listed matches on different consignments): their card has Clear — not a match and Block — confirmed match buttons for the whole group (each needs the adjudication note, as on the portal's page), and Work as one (since 7.66.0).
  - **Research all shown** (a switch under Manage account > Tools > Access code, off until ticked): a queue button that starts Claude Code research on every order the list shows, one per ×N stack, in background tabs: at most 28 an hour per routine, up to about 95 an hour with 4 routines (add copies of your routine under Manage account > Tools > Claude Code research; starts are spread over all of them). Already researched ones are skipped.
  - **Stack identical disputes in the queue** (a switch under Manage account > Tools > Access code, shown only once unlocked, and off until ticked): in Portal+, identical disputes with the same assignee and status show as one row with ×N. Claim or select that row and all N are claimed or selected; open it and it's worked as one. Claim, release, saved decisions and Submit on its page are done to all N (Submit after a 5-second countdown you can cancel).
  - **×N only** (next to Stack identical, since 7.70.0): shows just the rows that stand for identical copies, the one with the most copies first, so the biggest batches get worked first.
  - Denied-party reviews of the same party stack the same way (since 7.66.0). Worked as one, the Clear or Block you press on the lead's page, with its note, is done to the others after 5 seconds (with Cancel), and so are claim, release, mark waiting and notes.
  - **Work as one** opens one dispute of an identical group in the portal. Decisions you save there are copied to the rest, and when you press Submit you're asked whether to submit the rest too. Each copy is read again first and left alone if it no longer matches. Its bar at the bottom of the page minimizes (the – on it) to a small pill in the bottom-left corner that still shows progress and Cancel; ▴ brings it back (since 7.61.0).

## Settings (Manage account > Tools)

In the portal's account window (your avatar > **Manage account** > **Tools**), under the portal's own Tools settings, the **Dispute Deck** section. Saved in Tampermonkey on this computer, not with your account. Every section folds open:

- **Update:** checks GitHub for a newer version and opens the install page.
- **Portal pages.** Everything that changes the portal's own pages is off until you tick it:
  - the Entry Writer Queue page: Default Portal or Portal+
  - hiding escalated orders in Portal+ (on to start with)
  - easier-to-read order pages (labeled details, CBP messages in plain English)
  - denied-party "Listed on" links that open the official list (and copy the name) instead of a Google search
  - HS codes on the page opening in Entry Assistant
  - each order's codes loaded ahead in Entry Assistant (on by default)
- **Entry Assistant:** your own token, for the HTS facts in research prompts, including the duty calculator: each line's HTS code, origin and value are run through it, and the prompt lists every duty with its Chapter 99 code and the open questions (each naming the Chapter 99 code a yes brings) as research points. The reply answers each one from the research, and the calculator runs again with those answers: the resulting Chapter 99 codes go in the case doc.
- **Claude Code research** (optional): your cloud routine (and extra routines). With it, the Research tool's button is **Research in Claude Code**: the request goes in the sheet's Research tab and starts the routine, and the answer comes back into Notes and the case doc. A prompt too long for one sheet cell (a dispute with many lines, say) goes whole: the sheet keeps the rest in a hidden "Prompt parts" tab (since 7.59.0 and the sheet script of 2026-11-02.2). Also: add Claude Code's full research log to the case doc.
- **Earlier research into Notes:** **Fill in Notes** puts every duty dispute's past Claude answers and research chats in its Notes (see above).
- **Analytics:** opens Analytics.
- **Access code:** unlocks Batch work, bulk actions, Stack identical and Research all for the people given the code.
- **Back up or move your setup:** **Copy my setup** and **Import**. That text includes your keys, so keep it private.

Since 7.80.0 these aren't shown any more, but what was saved keeps working and still travels in the setup block: **Your name**, **Google Sheet** (it comes in the setup block), **Prompts** (the team edits them in the sheet's Prompts tab), **Shared answers** and **Search Slack & Front**. claude.ai answers are always saved now (there's no Save button to press), and the "Disputed program" names are no longer written onto the page (the prompts still carry them).

The script changes nothing in the portal except bulk actions you confirm and Claude's answers it adds to a dispute's Notes, and never sends anything on claude.ai.
